# Magpie Codex Guard：检测与隔离设计（统一状态机）

## 组件边界

- **Magpie 插件入口**：启动、关闭 Go 后端，提供本机控制台和短期 Cloudflare 临时远程控制台；不向浏览器暴露网关的 Secret。
- **Go 后端**：固定 Codex 登录账号或显式登记的 API 上游，执行自动客观题或指纹题、保存状态、隔离路由、管理自定义时间。正常检测不需要修改生产 Gateway Key。
- **指纹库**：每轮向固定账号发送 3 次独立随机数字题，只产生一次 `passed`、`failed` 或 `unavailable` 判分。纯本地参考库分析，不调用外部评分服务；没有专门的隔离后指纹复核。
- **SQLite**：持久化隔离 Hold、题库、全局与单目标时间策略、实际发送请求预算、检测历史及下一次复测时间。
- **生产路由控制器**：在 Magpie 文件锁与写前日志保护下修改受管理 Gateway Key 的路由范围；保持独立检测 Key 可用。只有管理员显式开启自动隔离才会写入。

## 统一状态和分题阈值

```text
正常 / 待测
  |
  +-- 普通客观题第一次错误 -> 原题重测 -> 第二次错误 -> 原题重测
  |                                              |
  |                                              +-- 第三次错误 ------+
  |                                                                   |
  +-- 指纹题：3 次有效采样归并为一轮 --- 一次可靠不一致 ---------------+
  |                                                                   |
  +-- 正确 -> 正常，按正常间隔重测                                    v
  +-- 429/超时/不可判定 -> 中性重试，不计错误                         隔离
                                                                      |
                                                              到期复测原题
                                                                      |
                                                          首次正确 -> 恢复确认
                                                                      |
                                                          第二次正确 -> 解除隔离
```

普通客观题的三次错误必须属于**同一道题**；指纹必须完整、可判定，三个原始样本本身不等于三次失败。指纹判为 `mismatch` 时**一次判定即可隔离**，`match` 为正确，`indeterminate`、上游失败、样本不足为中性结果。隔离后不再按高低风险区分时间。

恢复检测始终使用导致隔离的原题，连续两次有效正确才放行。隔离期间遇到无法判定不会放行，也不会清零此前的首次恢复通过。普通业务与后台采样均由 Magpie 的专用 Key 固定目标，绝不通过其他账号回退。

## 时间配置

全局和每个监测目标可以分别配置（单位：秒，管理页面支持适当换算为分钟/小时/天）：

| 字段 | 默认 |
| --- | --- |
| `normal_seconds` | 1800 |
| `suspect_seconds` | 120 |
| `quarantine_first_seconds` | 21600 |
| `quarantine_repeat_seconds` | 86400 |
| `recovery_seconds` | 120 |
| `unavailable_seconds` | 1800 |
| `request_timeout_seconds` | 180 |
| `scan_seconds`（仅全局） | 60 |

通过 `POST /api/timing` 保存至 SQLite，要求管理控制台的认证与同源保护；服务端执行数值范围校验。设置后**默认不重新计算已排定的检测时间**，只影响下一次排程；管理员可以单独选择 `reschedule`，不改变 Holds、失败次数或路由白名单。重启后保持存储中的截止时间，避免倒计时重复开始。

请求 429、超时、指纹不在库内或输出无法判定不会增加连续失败计数，按 `unavailable_seconds` 进行重试。缩短检测时间不会绕过每日上游请求限额。

## 自动参考模型映射

检测模型（例如 `codex/gpt-6.1-sol`）转换为指纹库支持的内部 ID（例如 `gpt-6-astra`）。只有明确匹配上固定本地参考模型的情况下，自动指纹题才会发起三个采样请求；不支持的模型不会被判错。高级手动覆盖仍可用于配置经过参考库验证的模型，默认不需要。

## 安全边界和升级迁移

1. 新隔离只有 `Risk="isolated"`，记录触发隔离的原题 `Prompt`；不再创建高/低风险隔离，也不再进入额外的 `fingerprint_pending` 阶段。
2. 从旧版升级时将历史 `high`、`low`、`pending` 持久化记录转换为统一隔离，但保留账号稳定 ID、开始时间、下次到期时间和路由排除状态；不得自动放行。
3. 自动隔离与恢复只有状态和结果成功保存后才能提交路由修改；若文件被管理员外部编辑，必须先核对实时生产 Gateway Key，再处理冲突。
4. Magpie 的空白名单不等于封锁全部；全部账号不可用时控制器可禁用受影响生产 Key，检测 Key 保持可用。
5. 删除的登录账号仍作为隔离留档；账号重新出现也不会绕过原隔离记录。自定义题库改变时不得无意清除已隔离账号的原题或状态。
6. 指纹概率是候选库内的相对统计评分，不是密码学身份验证；强不一致依照本地评分器校准阈值确定，仍需观察模式的真实账号验证。

上线前需备份 Magpie 生产 Key、旧版数据库及隔离记录；不得让两个插件控制器同时写同一组生产 Gateway Key。当前仍为开发测试版。
